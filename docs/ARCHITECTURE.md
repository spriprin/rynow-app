# Architecture and security decisions

## Runtime boundaries

The browser renders the mobile-first Next.js/Vinext interface and uses the Supabase anonymous client. Supabase Auth owns identity; PostgreSQL owns authorization and business invariants. Storage owns profile image bytes. Realtime streams only inserts that the current user can select through RLS.

```text
Browser → Supabase Auth → JWT with auth.uid()
Browser → PostgreSQL/RPC → RLS + database constraints
Browser → Realtime → messages allowed by match membership
Browser → Storage → public read, owner-folder write
```

The frontend may request an operation but cannot declare who it acts as. `auth.uid()` is resolved in the database.

## Privacy model

A profile can be discovered only when all of these are true:

1. viewer and target are active members of the same room;
2. the room is `LIVE`;
3. the target explicitly enabled `is_visible`;
4. neither user has blocked the other.

Matched users retain profile/chat access after room close. Non-matched discovery stops immediately. Exact coordinates, distance, map data and automatic social handles do not exist in the schema.

## Interest and match transaction

`send_interest(room, receiver)` runs as a security-definer database function. It verifies the authenticated sender, live room, active and visible memberships, and block state. It inserts one unique interest, checks the reciprocal direction in the same room, orders the pair by UUID, and upserts one unique match. There is no RLS policy allowing clients to insert matches directly.

## Acceptance flow mapping

- Organizer signup/profile role → `profiles.role`
- Create, edit and close room → `rooms` owner RLS
- QR → stable `/r/[slug]`, generated by the `qrcode` package
- Join → `join_room()` with unique `(room_id, user_id)`
- Visibility → `set_room_visibility()`
- Discovery → profile/membership RLS helpers
- Interest/match → `send_interest()`
- Chat → participant-only message policies + Supabase Realtime
- Organizer statistics → `room_analytics()`
- Close behavior → room status blocks discovery/interests; match/message policies remain valid

## Deployment shape

The web artifact is stateless and can run on Vercel or Sites-compatible Cloudflare infrastructure. Durable state remains in Supabase. This avoids microservices, Redis, background queues and other infrastructure not required by the MVP.
